# PBI-022: 埋め込みプロバイダーを ollama / openai で切り替え、指紋ごとにキャッシュする

- 担当モデル: (prepare.py の表から)
- 依存: PBI-018

## 目的
埋め込みを Ollama 専用から、設定の `provider`・`url`・`model` で選べる形にする (OpenAI 互換の `/embeddings` を足す)。あわせて、埋め込みの指紋を定義してキャッシュのキーにし、別のモデルのベクトルが混ざらないようにする。指紋は後続の PBI-024 がインデックスの照合に使う。

## 対象
- `packages/core/src/embed.ts`: 具象クラス `Embedder` を interface に変え、`createEmbedder`・`embeddingFingerprint`・`fingerprintParts`・`LEGACY_EMBEDDING` を export する。実装は ollama と openai の 2 つ (ref 01M5D344H4YBTX1D0F1Y193780 のとおり)
- `packages/core/test/embed.test.ts`: 偽サーバーでのテストに書き直す・足す
- `new Embedder(...)` を `createEmbedder(...)` に置き換える 3 か所: `packages/indexer/src/cli.ts`、`packages/mcp-server/src/app.ts`、`packages/core/test/int-helpers.ts`
- `packages/core/test/embed.int.test.ts`: `new Embedder` を使っていれば `createEmbedder` に直す

## 触らない範囲
- config.ts (PBI-018 で済み)、search.ts、indexing.ts (型 `Embedder` を import しているだけなので、interface に変えても直す必要は無いはず。型エラーが出たら import の形だけを直す)
- app.ts と cli.ts の、Embedder を作る行以外
- README.md、.gitignore、scripts/、lab/、docs/experiments/

## 受け入れ条件
1. 検証 1 が exit 0・`# fail 0`。偽サーバー (`http.createServer`、127.0.0.1:0) で次を確かめるテストを含むこと
   - ollama: `POST <url>/api/embed` に `{model, input, ...extra_body, ...document.params}` を送る。文書には `document.prefix`、クエリには `query.prefix` が前に付く
   - openai: `POST <url>/embeddings` に `{model, input, ...extra_body, ...params}` を送る。応答の `data[].embedding` を `index` の順に並べて使う (応答の並びが逆でも正しく対応する)
   - `api_key_env` があれば `authorization: Bearer <値>` が付き、無ければ付かない
   - `batch_size` でリクエストが分かれる
   - `normalize: true` で `[3, 4]` が `[0.6, 0.8]` になり、`false` ではそのまま
   - 次元が合わなければ例外になる。例外のメッセージに API キーの値が含まれない
   - 文書の埋め込みで 429 が 1 回返ると、`sleep` を挟んで再試行して成功する。5xx が 4 回続くと例外になる (最大 3 回の再試行)
   - `rpm: 60` では、2 回目のリクエストの前に約 1000ms の `sleep` が呼ばれる
   - クエリの埋め込みは 500 で再試行せずに例外になる
   - 2 回目の embedDocuments はキャッシュから返る (`cached` が増え、リクエストが出ない)
   - キャッシュは `<cacheDir>/<指紋>/...` に書かれる。設定が LEGACY_EMBEDDING と同じ指紋のときだけ、旧パス `<cacheDir>/qwen3-embedding_0_6b/<hash先頭2>/<hash>.json` のファイルを読む
   - 指紋は url・batch_size・rpm・api_key_env が違っても同じ。model・revision・document.prefix が違えば変わる
2. 検証 2 (型チェック) が exit 0
3. 検証 3 (単体テスト全体) が exit 0・`# fail 0`
4. 検証 4 が出力なし・exit 1 (`new Embedder` がどこにも残っていない)
5. 検証 5 (結合テスト。トンネル経由の実物の Ollama) が exit 0・`# fail 0`
6. 検証 6 が出力なし・exit 0

## 補足
- 仕様は `docs/specs/pluggable-embedding-and-rerank.md` の「埋め込みプロバイダー」。
- 再試行: 文書の埋め込み (embedDocuments) だけ。429 と 5xx で最大 3 回、待ち時間は `Retry-After` (秒) があればその値、無ければ 1000ms・2000ms・4000ms。rpm があれば、前回のリクエストから `60000 / rpm` ms たつまで待つ。待つのは必ず `opts.sleep` (既定は setTimeout) を通し、テストでは記録するだけの sleep を渡して実時間を待たない。
- HTTP は `opts.fetch ?? fetch` で呼ぶ。テストは既存の embed.test.ts と同じく偽の HTTP サーバーで行う (fetch のモックは使わない)。
- 正規化: L2 ノルムで割る。ノルムが 0 のベクトルはそのまま。キャッシュには正規化後のベクトルを書く。
- エラーメッセージの形: `Embedding (<provider>) failed: HTTP <status> <本文の先頭 300 字>`。
- 旧キャッシュのディレクトリ名は、今の embed.ts の `model.replace(/[^A-Za-z0-9]/g, "_")` と同じ規則で作る。
- int-helpers.ts は実リポジトリの設定を読んで Embedder を作っている。置き換えは `createEmbedder(cfg.embedding, cfg.cache_dir)` の 1 行でよい。
