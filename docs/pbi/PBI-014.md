# PBI-014: まとめ入力 (import コマンド)

- 担当モデル: opus
- 依存: PBI-010, PBI-013

## 目的
1 件ずつ MCP の `write` を呼ぶと毎回インデックスが走って遅いため、JSONL で複数のメモリをまとめて検証・作成し、インデックスを 1 回だけ更新する `import` コマンドを作る (設計書 `docs/design/design.md` 8.1章)。Skill `knowledge-import` がこのコマンドを使う。

## 対象 (リポジトリルート = `C:\Users\owner\dev\shared-memory`)
- `packages/core/src/import.ts` … `docs/design/interfaces.md` 14章 (`parseImportJsonl`, `planImport`, `commitImport`)
- `packages/indexer/src/cli.ts` … コマンド `import <file.jsonl> [--dry-run] [--source-agent <a>]` を対応表に足す (既存コマンドの挙動は変えない)
- `packages/core/test/import.test.ts` (新規。`parseImportJsonl` の単体テスト)
- `packages/core/test/import.int.test.ts` (新規。`packages/core/test/int-helpers.ts` の `makeTestEnv` を使う)

## 触らない範囲
- `packages/core/src/index.ts` と、`import.ts` 以外の `packages/core/src/*.ts`
- `packages/core/test/int-helpers.ts` (使うだけ)、`packages/mcp-server/`, `package.json`, `config.yaml`, `docs/`
- `cli.ts` の既存コマンドの実装

## 受け入れ条件
1. 検証コマンド1の TAP 出力が `# fail 0` で、`# pass` が 4 以上
2. 検証コマンド2の TAP 出力が `# fail 0` で、`# pass` が 4 以上
3. 検証コマンド3が終了コード 0
4. 検証コマンド4が終了コード 1 で、使い方に `import` を含む
5. 単体テストが少なくとも次を確認している: (a) 空行は飛ばす (b) JSON として壊れた行は行番号付きでエラー (c) provenance 省略で `agent_verified` (d) source_agent 省略で defaults の値、defaults も無ければエラー
6. 結合テストが少なくとも次を確認している: (a) 3 行の JSONL を `planImport`→`commitImport` で 3 ファイルでき、`report` の `upserted` が 1 以上で、`indexIncremental` の呼び出しが 1 回 (インデックス後のドキュメント数で確認してよい) (b) 秘密情報を含む行があると `planImport` の `errors` に入る (c) 同じバッチ内の重複行がエラー (d) 既存メモリを `supersedes` で指す行を取り込むと元メモリが `is_superseded`

## 補足
- 仕様の正本は `docs/design/interfaces.md` 14章。`prepareMemory` / `writeMemory` の検査ロジックは `memory-store.ts` (PBI-010) を再利用する (コピーしない)。ファイル書き込みは `writeFile(path, text, { flag: "wx" })`。
- (起動時に追記) 同じバッチ内で同じミリ秒の ULID が並ぶので、id がバッチ内で重複しないことを確かめる。ファイルの置き場所は `writeMemory` と同じく `memories_dir` 基準。本番データでの CLI 確認は `--dry-run` だけ。
- CLI の表示例: `新規 2 / 置き換え 1 / エラー 0` の後に各行 `  [新規] L1 <title>`。エラーがあれば `  [エラー] L4 <理由>` を出し、書き込まずに終了コード 1。
- テストに秘密情報の例を書くときは、実在しない値を文字列連結で組み立てる。
