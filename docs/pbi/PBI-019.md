# PBI-019: front matter に任意の source_path / source_sha256 を足し、import でも受け付ける

- 担当モデル: (prepare.py の表から)
- 依存: なし

## 目的
メモリを切り出した出典 (元の資料) をたどれるように、front matter に出典のパスとハッシュを任意で持てるようにする。中身は保存しない。

## 対象
- `packages/core/src/frontmatter.ts`: `MemoryMeta` に `source_path?: string` と `source_sha256?: string` を足す。`validateMeta` で検証し、読み込み (parse) と書き出し (serialize) で扱う
- `packages/core/test/frontmatter.test.ts`: テストを足す
- `packages/core/src/import.ts`: JSONL の行の `source_path` / `source_sha256` を受け付けて front matter に入れる
- `packages/core/test/import.test.ts`: テストを足す

## 触らない範囲
- `packages/core/src/chunk.ts` の `contentHash` (変えると全チャンクが再埋め込みになるため、出典の項目はハッシュに入れない)
- `opensearch/index-template.json` (出典はインデックスに入れない)
- README.md、.gitignore、scripts/、lab/、docs/experiments/

## 受け入れ条件
1. 検証 1 が exit 0・`# fail 0`。次のテストを含むこと: 2 つの項目を持つ front matter が検証を通り、書き出して読み直すと同じ値になる / 2 つとも無いメモリも今までどおり有効 / `source_path` が空文字・文字列以外ならエラー / `source_sha256` が 64 桁の小文字 16 進でなければエラー
2. 検証 2 が exit 0・`# fail 0`。JSONL の行に 2 つの項目を書くと作られるメモリの front matter に入り、不正な `source_sha256` の行はその行のエラーとして報告されるテストを含むこと
3. 検証 3 (型チェック) が exit 0
4. 検証 4 (単体テスト全体) が exit 0・`# fail 0`
5. 検証 5 が出力なし・exit 0

## 検証コマンド
1. `node --test --test-reporter=tap packages/core/test/frontmatter.test.ts`
2. `node --test --test-reporter=tap packages/core/test/import.test.ts`
3. `pnpm typecheck`
4. `pnpm test`
5. `python docs/pbi/tools/unchanged.py check PBI-019`

## 参照
なし

## 補足
- 仕様は `docs/specs/pluggable-embedding-and-rerank.md` の「出典」。
- 検証: `source_path` は空でない 1000 字以内の文字列、`source_sha256` は `/^[0-9a-f]{64}$/`。エラーメッセージは既存の validateMeta の日本語の書き方にそろえる。
- 書き出しの順序は既存の任意項目 (supersedes・symbol_ref・tags) のあとに source_path、source_sha256。値が undefined なら書かない。
- import.ts は行のオブジェクトを MemoryMeta に写している。既存の任意項目 (symbol_ref など) の扱いをそのままなぞる。
