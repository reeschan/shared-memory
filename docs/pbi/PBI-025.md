# PBI-025: 検索にリランクを組み込み、CLI と MCP で使う

- 担当モデル: (prepare.py の表から)
- 依存: PBI-021、PBI-022、PBI-023、PBI-024、PBI-020

## 目的
PBI-023 のリランカーを `searchMemories` に組み込む。候補は rescore 前の一次スコアで選び、リランクの順位をそのまま最終順位にする (ADR 0002)。失敗したらリランクなしの順位に戻す。あわせて、MCP 起動時と CLI の search で埋め込みの指紋の不一致を警告する。

## 対象
- `packages/core/src/search.ts`: `searchMemories` の deps に `reranker?: Reranker` と `log?: (msg: string) => void` を足す。`SearchResult` に `rerank_score?: number` を足す
- `packages/core/test/search-memories.test.ts` (新規): 偽の OpenSearch・Embedder・Reranker を渡す単体テスト
- `packages/indexer/src/cli.ts`: `createReranker(cfg.rerank)` を作り、search コマンドで deps に渡す。search コマンドの前に `checkEmbeddingCompat` を呼び、ok でなければ標準エラーに警告を出して続ける
- `packages/mcp-server/src/app.ts`: `createReranker(cfg.rerank)` を作り、search ツールの `searchMemories` に `reranker` と `log` (標準エラーへ) を渡す。起動時 (deps を作った直後) に `checkEmbeddingCompat` を 1 回呼び、ok でなければ標準エラーに警告を出す (起動は止めない。OpenSearch に届かないときの例外も警告にとどめる)

## 受け入れ条件
1. 検証 1 が exit 0・`# fail 0`。次を確かめるテストを含むこと
   - reranker が無いとき: 今までと同じく、メモリごとに最高スコアのチャンクを代表にし、rescore 後のスコアの降順で `limit` 件を返す。`rerank_score` は付かない
   - reranker があるとき: 一次スコア (`_score`) の上位 `rerank.candidates` 件のメモリの代表チャンクの本文が、その順で reranker に渡る。結果はリランクの点数の降順で、各結果に `rerank_score` が付き、`score` は rescore 後のスコアのまま
   - 候補の外 (candidates 位より下) のメモリは、一次スコアの降順でリランク済みのあとに続き、`rerank_score` は付かない
   - rescore では下位でも、一次スコアが高ければ候補に入る (rescore で候補を選んでいない)
   - reranker が例外を投げると、reranker が無いときと同じ順位を返し、`log` に `rerank failed` を含むメッセージが 1 回渡る
   - `limit` が candidates より小さいとき、上位 `limit` 件だけが返る
2. 検証 2 (型チェック) が exit 0
3. 検証 3 (単体テスト全体) が exit 0・`# fail 0`
4. 検証 4 の出力が 2 以上 (cli.ts と app.ts の両方で createReranker を呼んでいる)
5. 検証 5 (CLI の search。リランク無効の既定設定、トンネル経由の実物) が exit 0 で、JSON の配列が返る
6. 検証 6 (既存の結合テスト全体) が exit 0・`# fail 0`
7. 検証 7 が出力なし・exit 0

## 補足
- 仕様は `docs/specs/pluggable-embedding-and-rerank.md` の「リランク」、決定は `docs/adr/0002-rerank-before-rescore.md`。
- 代表チャンク: 1 つのメモリのチャンクのうち `_score` が最大のもの。rescore の係数はメモリ単位で同じなので、rescore 後でも同じチャンクが最大になる。
- 本文の切り詰め (`doc_max_chars`) は reranker の側で行う (PBI-023)。検索側では代表チャンクの `content` をそのまま渡す。
- テストの偽の OpenSearch は `search` メソッドだけを持つオブジェクトを `as unknown as OpenSearchClient` で渡す。cfg は `loadConfig()` を使ってよいが、`search.*`・`rerank.*` のうちテストに効く値はテストの中で明示的に上書きし、PC ごとの設定に依存しないようにする。`now` は固定の Date を渡す。
- 検証 5 は `pnpm sm` の出力形式に従う (`--json` で JSON)。出力が長ければ先頭だけを見て判定してよい。
