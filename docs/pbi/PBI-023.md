# PBI-023: リランカー (4 つの flavor) を足す

- 担当モデル: (prepare.py の表から)
- 依存: PBI-018

## 目的
検索結果の上位を並べ替えるリランカーを、設定の `flavor`・`url`・`model` で選べる形で用意する。検索への組み込みは後続の PBI-025 が行う。この PBI は単体で動くモジュールとテストまで。

## 対象
- `packages/core/src/rerank.ts` (新規): `Reranker` interface、`createReranker`、4 つの flavor の実装
- `packages/core/test/rerank.test.ts` (新規): 偽サーバーでのテスト
- `packages/core/src/index.ts`: `export * from "./rerank.ts";` を足す

## 触らない範囲
- search.ts、embed.ts、config.ts
- README.md、.gitignore、scripts/、lab/、docs/experiments/

## 受け入れ条件
1. 検証 1 が exit 0・`# fail 0`。偽サーバー (`http.createServer`、127.0.0.1:0) で次を確かめるテストを含むこと
   - cohere: `POST <url>/v1/rerank` に `{model, query, documents, top_n: 件数, ...extra_body}` を送り、`results[].index` と `relevance_score` を読む
   - voyage: `POST <url>/v1/rerank` に `{model, query, documents, top_k: 件数, ...extra_body}` を送り、`data[].index` と `relevance_score` を読む
   - tei: `POST <url>/rerank` に `{query, texts: documents, ...extra_body}` を送り、最上位の配列の `index` と `score` を読む
   - sarashina: `POST <url>/rerank` に `{model, query, documents, ...extra_body}` を送り、`data[0].result[]` の `document_id` と `relevance_score` (無ければ `score`) を読む。どちらも無ければ、返ってきた順に高い点数を割り当てる
   - `path` を設定すると既定のパスの代わりに使われる
   - 戻り値は score の降順で、すべての文書の index を 1 回ずつ含む
   - sarashina に 25 件を渡すと 20 件と 5 件の 2 リクエストに分かれ、2 回目の index に 20 が足されて統合される。`max_docs_per_request: 10` を設定すると 10 件ずつに分かれる
   - `doc_max_chars: 5` で、送られる文書が 5 文字 (コードポイント) に切られる
   - `api_key_env` があれば `authorization: Bearer <値>` が付く
   - 応答が `timeout_ms` (テストでは 100ms) より遅いと、例外になる
   - HTTP 500 や形の不正な応答で例外になる。例外のメッセージに API キーの値が含まれない
   - documents が空なら、リクエストを出さずに `[]` を返す
   - `enabled: false` なら `createReranker` は `undefined` を返す
2. 検証 2 (型チェック) が exit 0
3. 検証 3 (単体テスト全体) が exit 0・`# fail 0`
4. 検証 4 が出力なし・exit 0

## 補足
- 仕様は `docs/specs/pluggable-embedding-and-rerank.md` の「リランク」。
- flavor ごとの 1 リクエストあたりの既定の上限 (`max_docs_per_request: 0` のとき): cohere 1000、voyage 1000、tei 32、sarashina 20。
- タイムアウトは rerank の 1 回の呼び出し全体で 1 つ (`AbortSignal.timeout(timeout_ms)`)。分けたリクエストすべてに同じ signal を渡す。
- URL は `url` の末尾の `/` を除き、パスをつなぐ。
- エラーメッセージの形: `Rerank (<flavor>) failed: HTTP <status> <本文の先頭 300 字>`、形の不正は `Rerank (<flavor>): unexpected response`。
- この PBI の Reranker はフォールバックをしない (例外を投げるだけ)。フォールバックは PBI-025 の検索側で行う。
- テストの書き方は既存の `packages/core/test/embed.test.ts` (偽の HTTP サーバー) に合わせる。設定のオブジェクトはテストの中で組み立てる。
