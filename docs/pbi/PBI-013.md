# PBI-013: tier の降格 (decay) と GC

- 担当モデル: opus
- 依存: PBI-011

## 目的
最終アクセス日から tier を再計算して検索対象を絞る `decay` (1 日 1 回) と、置き換え済みメモリの archive 送り・`symbol_ref` 参照切れの一覧を出す `gc` (週 1 回) を実装する (設計書 `docs/design/design.md` 6.2・6.3章)。ファイルは消さない。

## 対象 (リポジトリルート = `C:\Users\owner\dev\shared-memory`)
- `packages/core/src/tiers.ts` … `docs/design/interfaces.md` 13章 (`computeTier`, `syncTiers`, `runDecay`, `runGc`)
- `packages/indexer/src/cli.ts` … コマンド `decay` と `gc` を対応表に足す (既存の 4 コマンドの挙動は変えない)。`gc` は `brokenSymbolRefs` を 1 行ずつ表示する。
- `packages/core/test/tiers.test.ts` (新規。`computeTier` の単体テスト)
- `packages/core/test/tiers.int.test.ts` (新規。`packages/core/test/int-helpers.ts` の `makeTestEnv` を使う)

## 触らない範囲

## 受け入れ条件
1. 検証コマンド1の TAP 出力が `# fail 0` で、`# pass` が 7 以上
2. 検証コマンド2の TAP 出力が `# fail 0` で、`# pass` が 3 以上
3. 検証コマンド3が終了コード 0
4. 検証コマンド4が終了コード 1 で、使い方に `decay` と `gc` を含む
5. 単体テストが少なくとも次を確認している (warm 7 / cold 30 / archive 180 日): 経過 3 日→hot、10 日→warm、40 日→cold、200 日→archive、`last_accessed_at` があればそちらを使う、human_confirmed は 200 日でも warm、superseded は human_confirmed でも archive
6. 結合テストが少なくとも次を確認している: (a) `created_at` が 40 日前のメモリで `runDecay` → `changed` に hot→cold が入り、OpenSearch のドキュメントの tier が cold、その後の `searchMemories` で出ない (b) 2 回目の `runDecay` は `changed` が空 (c) superseded のメモリが `runGc` で archive になる (d) `scope: repo:foo`・`symbol_ref` 付きで `repos` 未登録のメモリが `brokenSymbolRefs` に入る

## 補足
- 仕様の正本は `docs/design/interfaces.md` 13章。日付の差は `(now - Date.parse(x)) / 86400000`。
- `syncTiers` の `updateByQuery` は tier ごとに 1 回 (`terms memory_id`)。対象 0 件なら呼ばない。
- 結合テストの「40 日前」はメモリファイルの `created_at` を過去日にして作る。`runDecay` の `now` 引数を使ってもよい。
- `symbol_ref` の存在確認はファイルを 1 つずつ読み、名前の部分文字列一致で判定する (1 MB を超えるファイルとバイナリっぽいもの (NUL を含む) は飛ばす)。
