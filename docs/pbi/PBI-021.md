# PBI-021: rescore を弱める (soft rescore)

- 担当モデル: (prepare.py の表から)
- 依存: PBI-018

## 目的
評価では、今の rescore (時間減衰 × アクセス回数 × 出所) だけで nDCG@10 が 0.884 から 0.694 に下がった。減衰に下限を付け、アクセスの係数を弱めた式 (soft) にすると 0.859 まで戻る。リランクが無効のときにも効くよう、本番の rescore をこの式に変える。

## 対象
- `packages/core/src/search.ts` の `rescore` 関数
- `packages/core/test/search.test.ts`: rescore のテストを新しい式に合わせて足す・直す

## 触らない範囲
- `searchMemories`・`buildHybridQuery`・`buildFilter` (後続の PBI-025 が searchMemories を変える)
- config.ts・config.yaml (PBI-018 で `search.rescore` は入っている)
- README.md、.gitignore、scripts/、lab/、docs/experiments/

## 受け入れ条件
1. 検証 1 が exit 0・`# fail 0`。次を確かめるテストを含むこと (decay_floor 0.7・access_weight 0.2 を config で与える)
   - 減衰 0 に近い古いメモリでも、係数の下限が 0.7 になる
   - アクセス回数 0 では、アクセスの係数が 1
   - アクセス回数 e−1 回相当 (たとえば 2 回なら `1 + 0.2 × ln 3`) で、式どおりの値になる
   - 出所の係数が掛かる
   - decay_floor 1.0・access_weight 0 にすると、一次スコア × 出所の係数だけになる
2. 検証 2 (型チェック) が exit 0
3. 検証 3 (単体テスト全体) が exit 0・`# fail 0`
4. 検証 4 が出力なし・exit 0

## 補足
- 新しい式: `rescore = hybridScore × (decay_floor + (1 − decay_floor) × decay) × (1 + access_weight × ln(1 + access_count)) × provenance_factor`。`decay` は今の計算 (半減期による 0.5 の累乗) のまま。lab/eval.mjs の `mode === "soft"` と同じ式 (lab は読むだけで変えない)。
- search.test.ts は今 `loadConfig()` で実リポジトリの設定を読んでいる。足すテストでは `cfg.search.rescore` と `half_life_days`・`provenance_factor` をテストの中で明示的に上書きし、PC ごとの設定に依存しないようにする。
