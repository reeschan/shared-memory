# PBI-009: core のハイブリッド検索と再スコア

- 担当モデル: opus
- 依存: PBI-008

## 目的
MCP の `search` の中身を実装する。OpenSearch のハイブリッドクエリ (BM25 + kNN、Search Pipeline で正規化) で候補を取り、サーバー側で時間減衰・アクセス回数・出所の係数をかけて再スコアし、メモリ単位にまとめて返す (設計書 `docs/design/design.md` 5.2章)。

## 対象 (リポジトリルート = `C:\Users\owner\dev\shared-memory`)
- `packages/core/src/search.ts` … `docs/design/interfaces.md` 9章 (`SearchInput`, `SearchResult`, `buildFilter`, `buildHybridQuery`, `rescore`, `searchMemories`)
- `packages/core/test/search.test.ts` (新規。単体テスト)
- `packages/core/test/search.int.test.ts` (新規。`packages/core/test/int-helpers.ts` の `makeTestEnv` を使う)

## 触らない範囲
- `packages/core/src/index.ts` と、`search.ts` 以外の `packages/core/src/*.ts`
- `packages/core/test/int-helpers.ts` (使うだけ)
- `opensearch/`, `package.json`, `config.yaml`, `docs/`
- 本番のエイリアス `memories` (テストは `test-` で始まる名前だけ)

## 受け入れ条件
1. 検証コマンド1の TAP 出力が `# fail 0` で、`# pass` が 6 以上
2. 検証コマンド2の TAP 出力が `# fail 0` で、`# pass` が 4 以上
3. 検証コマンド3が終了コード 0
4. 単体テストが少なくとも次を確認している: (a) `buildFilter` が scope/kind/tags 未指定なら 2 条件、全部指定で 5 条件 (b) `buildHybridQuery` の queries が BM25 → kNN の順で、両方に同じ filter が入る (c) `rescore`: 経過 0 日・access 0・human_confirmed でハイブリッドスコアと同じ値 (d) 経過日数 = half_life でちょうど半分 (e) agent_inferred は human_confirmed の 0.7 倍 (f) access_count が多いほど高い
5. 結合テストが少なくとも次を確認している: (a) 日本語の内容が違う 5 件ほどのメモリを投入し、そのうち 1 件の内容に関する質問文で、そのメモリが 1 位 (b) `is_superseded` のメモリが結果に出ない (c) scope 指定で他 scope が出ない (d) 同じメモリの複数チャンクがヒットしても結果は 1 件にまとまる (e) `excerpt` が 160 字以下で title の接頭辞を含まない

## 検証コマンド
1. `node --test --test-reporter=tap packages/core/test/search.test.ts`
2. `node --test --test-reporter=tap --test-concurrency=1 packages/core/test/search.int.test.ts`
3. `pnpm typecheck`

## 補足
- 仕様の正本は `docs/design/interfaces.md` 0章・9章。
- 検索は `os.search(cfg.opensearch.alias, body, { search_pipeline: cfg.opensearch.pipeline_name })`。ハイブリッドクエリは他のクエリで包めない (トップレベルの `query.hybrid` にする)。
- 結合テストのデータ投入は `indexIncremental` (PBI-008) を使う。ヘルパーの使い方は `packages/core/test/indexing.int.test.ts` を参照。
