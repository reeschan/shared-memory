# PBI-005: core の埋め込みクライアント (Ollama + ファイルキャッシュ)

- 担当モデル: sonnet
- 依存: PBI-003

## 目的
ローカルの Ollama (Qwen3-Embedding-0.6B) で文書とクエリをベクトル化するクライアントを作る。インデクサと MCP サーバーが同じクライアントを共有し、インストラクションと次元の食い違いを防ぐ。文書ベクトルはローカルファイルにキャッシュする。

## 対象 (リポジトリルート = `C:\Users\owner\dev\shared-memory`)
- `packages/core/src/embed.ts` … `docs/design/interfaces.md` 5章 (`Embedder`)
- `packages/core/test/embed.test.ts` (新規。`node:http` でテスト用の偽 Ollama サーバーを 127.0.0.1 のランダムポートに立てる)
- `packages/core/test/embed.int.test.ts` (新規。本物の Ollama `http://127.0.0.1:11434` を使う)

## 触らない範囲
- `packages/core/src/index.ts` と、`embed.ts` 以外の `packages/core/src/*.ts` (`config.ts` の `Config` 型は `import type` で使うだけ)
- `package.json`, `config.yaml`, `docs/`
- リポジトリの `.cache/` (テストのキャッシュは `os.tmpdir()` 配下の一時ディレクトリに作り、終わったら消す)

## 受け入れ条件
1. 検証コマンド1の TAP 出力が `# fail 0` で、`# pass` が 5 以上
2. 検証コマンド2の TAP 出力が `# fail 0` で、`# pass` が 1 以上
3. 検証コマンド3が終了コード 0
4. 単体テストが少なくとも次を確認している: (a) 2 回目の `embedDocuments` は偽サーバーへのリクエストが増えずキャッシュから返る (`cached` が件数と一致) (b) `batch_size` ごとに分けて送る (c) `embedQuery` は送る文字列の先頭に `query_instruction` が付き、`embedDocuments` は付かない (d) 次元が違う応答で throw (e) HTTP 500 で throw
5. 結合テストが、本物の Ollama で `embedQuery("テスト")` の長さが 1024 であることを確認している

## 検証コマンド
1. `node --test --test-reporter=tap packages/core/test/embed.test.ts`
2. `node --test --test-reporter=tap packages/core/test/embed.int.test.ts`
3. `pnpm typecheck`

## 補足
- 仕様の正本は `docs/design/interfaces.md` 0章と5章。
- Ollama は起動済みで `qwen3-embedding:0.6b` を pull 済み。API は `POST /api/embed` body `{"model":"qwen3-embedding:0.6b","input":["..."]}` → `{"embeddings":[[...1024個...]]}`。
- テストでは `Config["embedding"]` 相当のオブジェクトを直接組み立ててよい (`loadConfig` を使わなくてよい)。
