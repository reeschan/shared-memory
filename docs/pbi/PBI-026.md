# PBI-026: README・設定の例・インターフェース文書を、プロバイダー切り替えと Mac/Linux に合わせて整える

- 担当モデル: (prepare.py の表から)
- 依存: PBI-025、PBI-024、PBI-027

## 目的
実装した埋め込みプロバイダー・リランカー・出典の項目の使い方と、Mac/Linux でのセットアップ手順を、README と設定の例に書く。今の README は Windows 前提になっている。

## 対象
- `README.md`: 作業ツリーに本件と無関係な未コミットの変更がある。その変更を消さずに、その上に書き足す (ファイル全体を書き直さず、該当の節を Edit で直す)
- `config.local.example.yaml`: Mac・Linux のパスの例、埋め込みとリランクの切り替えの例 (コメント) を足す
- `docs/design/interfaces.md`: Embedder・Reranker・searchMemories の契約の節を新しい形に直す

## 触らない範囲
- README の「コードの配布」節の既存の文 (本件と無関係の未コミット変更。Windows 限定と明記する 1 文を足すのはよい)
- packages/、config.yaml、docker-compose.yml、skills/、scripts/、lab/、docs/experiments/

## 受け入れ条件
1. README に次の節・内容がある (検証 1 の出力が 8 以上)
   - 前提を OS ごと (Windows / macOS / Linux) に書く: Docker (Docker Desktop / OrbStack / colima / Docker Engine)、Ollama、Node 26 (fnm か mise)、pnpm (`npm i -g pnpm@12`)
   - セットアップのコマンドを PowerShell と bash の 2 通りで書く
   - `vm.max_map_count` は、OpenSearch が起動しないときや警告が出たときに設定する任意の手順とする (Linux は `sysctl`、Docker Desktop / colima / OrbStack ではその VM の中で設定)
   - Mac/Linux での常駐: MCP サーバーの常駐と `decay`(毎日)・`gc`(毎週) の定期実行を、launchd の plist と systemd --user の service / timer の雛形で示す (node の絶対パスを書く注意、Linux の `loginctl enable-linger`)
   - クライアント構成: サーバー PC へ `ssh -N -L 127.0.0.1:7820:127.0.0.1:7820 <user>@<サーバー PC>` を張る例と、それを常駐させる launchd / systemd の雛形
   - サーバー集約構成とコードの自動配布 (`publish-code.mjs`・`deploy-code.ps1`・`register-tasks.ps1`) は Windows のサーバー PC 限定と明記
   - 「埋め込みモデルの切り替え」の節: `provider` (ollama / openai) と各項目、例 (今の Ollama の既定、LM Studio などの OpenAI 互換、Sarashina の `batch_size: 1`・`rpm: 60`・`query.params.task_type: RETRIEVAL_QUERY`・`document.params.task_type: RETRIEVAL_DOCUMENT`・`api_key_env`)、API キーは `.env` に書くこと、設定を変えると `index` が止まり `pnpm sm reindex` で作り直すこと、同じ名前で中身の違うモデルは `revision` を上げること
   - 「リランク」の節: 既定は無効、`flavor` の 4 種類と対応するサーバー (cohere 形: Cohere・Jina・Infinity・vLLM・llama.cpp)、例 (TEI のローカル、Sarashina の `extra_body.task_type: GENERAL_RETRIEVAL`)、TEI を `docker compose --profile rerank up -d` で起動する手順、遅延の目安 (外部 API で約 1 秒)、失敗時はリランクなしで返ること
   - 外部 API に本文を送るのは設定で明示したときだけであること、Sarashina の無償ベータでは送った内容が改善に使われうること
   - メモリファイルの書式の表に `source_path` / `source_sha256` (任意) を足し、MCP ツールの `write` の説明にも足す
   - Skill (mcp-setup・knowledge-import) は Windows 以外では `SHARED_MEMORY_ROOT` が必須であること
2. 検証 2 の出力が 3 以上 (config.local.example.yaml に Mac/Linux のパスの例と provider・rerank の例がある)
3. 検証 3 の出力が 3 以上 (interfaces.md に createEmbedder・createReranker・rerank_score の記述がある)
4. 検証 4 の出力に、作業前からあった README の変更 (「コードの配布」節) が残っている (1 以上)
5. 検証 5 が出力なし・exit 0
