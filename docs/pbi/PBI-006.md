# PBI-006: core の OpenSearch クライアント (fetch 製の薄いラッパー)

- 担当モデル: sonnet
- 依存: PBI-001, PBI-002

## 目的
インデクサと MCP サーバーが OpenSearch を操作するための薄いクライアントを `fetch` で作る。クライアントライブラリは使わない。

## 対象 (リポジトリルート = `C:\Users\owner\dev\shared-memory`)
- `packages/core/src/opensearch.ts` … `docs/design/interfaces.md` 6章 (`OpenSearchClient`)
- `packages/core/test/opensearch.int.test.ts` (新規。起動中の `http://127.0.0.1:9200` を使う)

## 触らない範囲
- `packages/core/src/index.ts` と、`opensearch.ts` 以外の `packages/core/src/*.ts`
- `opensearch/`, `docker-compose.yml`, `package.json`, `config.yaml`, `docs/`
- テスト用以外のインデックス・エイリアス (テストで作るものは名前を `test-pbi006-` で始め、テストの最後に必ず消す)

## 受け入れ条件
1. 検証コマンド1の TAP 出力が `# fail 0` で、`# pass` が 6 以上
2. 検証コマンド2が終了コード 0
3. 検証コマンド3の出力に `test-pbi006` を含まない (後片付けされている)
4. 結合テストが少なくとも次を確認している: (a) `createIndex`→`indexExists` が true、`deleteIndex` 後 false (b) `getAliasTargets` が存在しないエイリアスで `[]`、`swapAlias` 後に新インデックスを指す (c) `bulk` で 3 件 index→`refresh`→`search` で 3 件 (d) `bulk` に不正な操作を混ぜると `errors: true` と `failed` に id が入る (e) `scanAll` が 1500 件を取りこぼさず返す (scroll の 2 ページ目以降も取る) (f) `updateByQuery` が更新件数を返し値が変わる (g) 存在しないインデックスの `scanAll` が `[]`

## 検証コマンド
1. `node --test --test-reporter=tap packages/core/test/opensearch.int.test.ts`
2. `pnpm typecheck`
3. `curl -s "http://127.0.0.1:9200/_cat/indices?h=index"`

## 補足
- 仕様の正本は `docs/design/interfaces.md` 0章と6章。
- OpenSearch は PBI-002 の `docker compose up -d` で起動済み (セキュリティ無効・認証なし)。
- bulk の body は NDJSON で、最後に改行が必要。`Content-Type: application/x-ndjson`。
- scroll は `POST /<index>/_search?scroll=1m` → `POST /_search/scroll` を繰り返し、最後に `DELETE /_search/scroll` で解放する。
