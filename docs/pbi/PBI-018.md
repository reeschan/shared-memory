# PBI-018: 設定に embedding の新しい項目・rerank・search.rescore を足し、.env と API キーを読む

- 担当モデル: (prepare.py の表から)
- 依存: なし

## 目的
埋め込みプロバイダーとリランカーを設定で切り替えるための土台。設定の型と検証を ref の形にそろえ、後続の PBI (埋め込み・リランク・rescore) がこの型を前提に書けるようにする。

## 対象
- `packages/core/src/config.ts`: Config 型・既定値の補完・検証・旧キーの読み替え・`.env` の読み込み・`resolveApiKey` の export
- `config.yaml`: `embedding.query_instruction` を `embedding.query.prefix` に移す (文字列はそのまま)。`provider: ollama`・`normalize: true`・`document: { prefix: "", params: {} }` を足す。`rerank:` セクション (enabled: false と既定値、コメントで flavor の選択肢) と `search.rescore: { decay_floor: 0.7, access_weight: 0.2 }` を足す
- `packages/core/test/config.test.ts`: テストを足す
- `packages/core/src/embed.ts`: `this.cfg.query_instruction` を `this.cfg.query.prefix` に変える 1 行だけ (型が通るようにするため。ほかは変えない)
- `packages/core/test/embed.test.ts` と `packages/core/test/embed.int.test.ts`: 設定のオブジェクトを新しい型に合わせる (`query_instruction: X` → `provider: "ollama", normalize: false, revision: 0, extra_body: {}, query: { prefix: X, params: {} }, document: { prefix: "", params: {} }`)。テストの期待値は変えない

## 補足
- 仕様は `docs/specs/pluggable-embedding-and-rerank.md` の「API キーと設定の検証」。
- 今の loadConfig は必須キーの有無だけを見て `as unknown as` で返している。既定値の補完と検証は、`embedding`・`rerank`・`search.rescore` に限って関数を分けて足す (ほかのセクションは今のまま)。
- `.env` の読み込みは `node:util` の `parseEnv` を使い、`<root>/.env` を読む (cwd 基準ではない)。テストでは一時ディレクトリに `config.yaml`・`pnpm-workspace.yaml`・`.env` を置き、`loadConfig(<一時ディレクトリ>)` で確かめる。テストで process.env に入れた値は後で消す。
- テストでは一時ディレクトリの config.yaml に必須キーをすべて書く必要がある (REQUIRED)。既存の config.test.ts の書き方を参考にする。
- エラーメッセージは日本語で、既存の `config.yaml: 必須キー ... がありません` の書き方にそろえる。API キーの値はメッセージに入れない。
