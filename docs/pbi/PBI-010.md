# PBI-010: core のメモリ読み書き (write・read・アクセス記録)

- 担当モデル: opus
- 依存: PBI-008

## 目的
MCP の `write` と `get` の中身を実装する。`write` は必須フィールドと秘密情報を検査してから Markdown を新規作成し、そのファイルだけをインデックスする (ガバナンスはここで強制する)。`get` は本文を返し、アクセス統計を SQLite と OpenSearch に反映する。

## 対象 (リポジトリルート = `C:\Users\owner\dev\shared-memory`)
- `packages/core/src/memory-store.ts` … `docs/design/interfaces.md` 10章 (`WriteInput`, `findMemoryPath`, `readMemory`, `prepareMemory`, `writeMemory`, `recordAccess`)
- `packages/core/test/memory-store.test.ts` (新規。`prepareMemory` の単体テスト)
- `packages/core/test/memory-store.int.test.ts` (新規。`packages/core/test/int-helpers.ts` の `makeTestEnv` を使う)

## 触らない範囲
- `packages/core/src/index.ts` と、`memory-store.ts` 以外の `packages/core/src/*.ts`
- `packages/core/test/int-helpers.ts` (使うだけ)
- `package.json`, `config.yaml`, `docs/`, リポジトリの `memories/` と `state/` (テストは一時ディレクトリだけ)

2. 検証コマンド2の TAP 出力が `# fail 0` で、`# pass` が 4 以上

4. 単体テストが少なくとも次を確認している: (a) 正しい入力で ULID の id と `created_at` が付く (b) provenance が列挙外でエラー (c) content に GitHub トークン形式の文字列を含むとエラー (d) 存在しない `supersedes` でエラー (e) 空の content でエラー
5. 結合テストが少なくとも次を確認している: (a) `writeMemory` で `memories/<scopeのディレクトリ>/<id>.md` ができ、直後にそのメモリが OpenSearch にある (b) `supersedes` 付きの write で元メモリの `is_superseded` が true になる (c) `readMemory` で front matter と本文が返り、無い id は undefined (d) `recordAccess` を 2 回で StatsStore の count が 2、OpenSearch のドキュメントの `access_count` も 2・`tier` が hot

## 補足
- 仕様の正本は `docs/design/interfaces.md` 0章・10章。
- 既存ファイルの上書きを防ぐため、書き込みは `writeFile(path, text, { flag: "wx" })`。
- (起動時に追記) ファイルの置き場所は `memories_dir` 基準にする。`memoryRelPath(meta, path.basename(cfg.memories_dir))` の先頭要素を除いた部分を `cfg.memories_dir` に join する。`indexIncremental` の `only` には絶対パスを渡してよい。
- テストに秘密情報の例を書くときは、実在しない値を文字列連結で組み立てる (例 `"ghp_" + "a".repeat(36)`)。
- `recordAccess` の OpenSearch 反映は painless スクリプト (`ctx._source.access_count = params.c; ...`) で `updateByQuery`。
