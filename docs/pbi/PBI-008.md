# PBI-008: core のインデクサ本体 (差分インデックス・全件再構築)

- 担当モデル: opus
- 依存: PBI-002, PBI-003, PBI-004, PBI-005, PBI-006, PBI-007

## 目的
Markdown (正) から OpenSearch (派生) を作る処理を実装する。差分インデックスは CLI の `index` と MCP の `write` が共有し、全件再構築は `reindex` が使う。設計書 `docs/design/design.md` 3.3章・6.1章の挙動を、`docs/design/interfaces.md` 8章の関数として実装する。

## 対象 (リポジトリルート = `C:\Users\owner\dev\shared-memory`)
- `packages/core/src/indexing.ts` … `docs/design/interfaces.md` 8章 (`Deps`, `scanMemories`, `computeSuperseded`, `ensureSetup`, `IndexReport`, `indexIncremental`, `reindexAll`)
- `packages/core/test/int-helpers.ts` (新規) … 結合テスト用の共通ヘルパー。`makeTestEnv(name: string)` が `loadConfig()` の結果を複製し、`opensearch.alias` と `opensearch.index_base` を `test-<name>-<乱数>`、`memories_dir` と `state_db` を `os.tmpdir()` 配下の新しい一時ディレクトリ、`cache_dir` を `os.tmpdir()/shared-memory-test-cache` に差し替えた `Config` と、`Deps` (`OpenSearchClient`・`Embedder`・`StatsStore`)、メモリファイルを書く関数 `writeMemoryFile(meta, body)`、後片付け `cleanup()` (テスト用インデックス・エイリアス・一時ディレクトリを消す) を返す。後続の PBI もこのヘルパーを使う。
- `packages/core/test/indexing.int.test.ts` (新規)

## 触らない範囲
- `packages/core/src/index.ts` と、`indexing.ts` 以外の `packages/core/src/*.ts` (他モジュールは呼ぶだけ。不具合を見つけたら直さずに報告する)
- `opensearch/` の JSON ファイル (読むだけ)、`package.json`, `config.yaml`, `docs/`
- エイリアス `memories` と `memories-qwen3-0.6b-v1` 系の本番インデックス (テストは必ず `test-` で始まる名前だけを使う)

## 受け入れ条件
1. 検証コマンド1の TAP 出力が `# fail 0` で、`# pass` が 7 以上
2. 検証コマンド2が終了コード 0
3. 検証コマンド3の出力に `test-` で始まるインデックスを含まない (後片付けされている)
4. 結合テストが少なくとも次を確認している:
   (a) `ensureSetup` がエイリアスとインデックスを作り、2 回目は作らない (`createdIndex` が undefined) ・パイプラインが登録され weights が config の値
   (b) 3 ファイル (うち 1 つは見出しが複数で 2 チャンク以上) を `indexIncremental` → ドキュメント数がチャンク数と一致、`_id` が `<id>:<chunk_no>`
   (c) 何も変えずに 2 回目の `indexIncremental` → `embedded` 0・`upserted` 0
   (d) 1 ファイルの本文を変える → そのファイルのチャンクだけ `upserted`
   (e) 不正な front matter のファイルは `invalid` に入り、他は投入される
   (f) `supersedes` で A を指す B を追加 → A の全チャンクの `is_superseded` が true
   (g) ファイルを削除 → そのメモリのドキュメントが消える (`deleted` > 0)
   (h) StatsStore に access_count=5 を入れてから `indexIncremental` → ドキュメントの `access_count` が 5
   (i) `reindexAll` が新しいインデックスを作ってエイリアスを付け替え、旧インデックスを削除する。件数は同じ

## 補足
- 仕様の正本は `docs/design/interfaces.md` 0章・6〜8章。手順の番号は 8章の `indexIncremental` 1〜6。
- OpenSearch (`http://127.0.0.1:9200`) と Ollama (`http://127.0.0.1:11434`, `qwen3-embedding:0.6b`) は起動済み。
- 本番と同じ `opensearch/index-template.json` をそのまま使ってテスト用インデックスを作る (Sudachi アナライザーが入っている)。
- パイプライン名もテストごとに `test-<name>-<乱数>-pipeline` に差し替え、後片付けで消す (`DELETE /_search/pipeline/<name>`)。
- ドキュメントの `created_at` / `last_accessed_at` は ISO 文字列、`last_accessed_at` が null のときはフィールドを null のまま入れてよい。
- ファイル走査は `node:fs/promises` の `readdir(dir, { recursive: true })`。Windows ではパス区切りが `\` になるので `/` に直してから `parseMemoryFile` に渡す。 `parseMemoryFile` に渡す relPath は `memories/<scope dir>/<id>.md` の形。先頭のディレクトリ名は `path.basename(cfg.memories_dir)` を使い、ヘルパーの一時ディレクトリは最後の要素が `memories` になるように作る (例 `<tmp>/<rand>/memories`)。(起動時に追記)
