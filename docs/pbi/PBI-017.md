# PBI-017: 運用スクリプトの不具合修正 (スモークテストの誤判定・Codex の承認・ログの文字化け)

- 担当モデル: sonnet
- 依存: PBI-015

## 目的
PBI-015 で作った運用スクリプトを本実行したところ、不具合が 3 つ見つかった。どれも登録処理そのものは正しく、確認とログの部分だけが壊れている。

1. `skills/mcp-setup/register.ps1 -SmokeTest` が、エージェントの答えではなく、出力にエコーされた指示文の中の `SM_SMOKE_OK` を拾って「結果あり」と誤判定する (Codex で再現)。
2. Codex の非対話実行 (`codex exec`) では MCP ツールの呼び出しに承認が要り、`MCP tool call requires approval, but approval policy is never` で失敗する。`-c 'mcp_servers.shared-memory.default_tools_approval_mode="approve"'` を付けると成功することを確認済み。
3. `scripts/register-tasks.ps1` が登録する Decay / GC タスクのログ (`.cache/logs/SharedMemory-*.log`) が文字化けする。node は UTF-8 で出力するが、PowerShell 5.1 がそれを CP932 として読んでから UTF-8 で書いているため (例: `メモリ 20 件` が `繝｡繝｢繝ｪ 20 莉ｶ` になる)。

## 対象 (リポジトリルート = `C:\Users\owner\dev\shared-memory`)
- `skills/mcp-setup/register.ps1` … スモークテストの部分だけ直す。
  - 判定は、エージェントの出力のうち `^\s*[•*-]?\s*SM_SMOKE_(OK|EMPTY|FAIL)\b` に当たる行のうち**最後の行**だけで行う (指示文のエコーは先に出るため)。指示文には `<件数>` などのプレースホルダを書かず、答えの形を「`SM_SMOKE_OK` の後に件数」のように言葉で説明する。
  - Codex のスモークテストだけ `codex exec --skip-git-repo-check -c 'mcp_servers.shared-memory.default_tools_approval_mode="approve"' "<指示>"` で呼ぶ (ユーザーの config.toml は変えない)。
  - エージェントの出力を読むときに UTF-8 として扱う (`[Console]::OutputEncoding = [System.Text.Encoding]::UTF8` をスモークテストの前に設定し、終わったら元に戻す)。
- `scripts/register-tasks.ps1` … Decay / GC タスクの実行コマンドで、node を呼ぶ前に `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8` を設定し、ログが UTF-8 の正しい日本語になるようにする。登録内容の他の部分 (トリガー・名前・ログの場所) は変えない。

## 触らない範囲
- `register.ps1` のスモークテスト以外の部分 (疎通確認・登録・Skill 配置・指示ファイル追記)
- `scripts/start-mcp.ps1`, `skills/*/SKILL.md`, `packages/`, `docs/`, `README.md`, `memories/`, `config.yaml`
- ユーザー環境: `register-tasks.ps1` と `register.ps1` は**本実行しない** (登録済みの内容の更新はオーケストレーターが行う)。確認は下の検証コマンドだけで行う。`~/.codex/config.toml` を変えない。

## 受け入れ条件
1. 検証コマンド1が `OK` を 3 回出力する
2. 検証コマンド2の出力に `[Console]::OutputEncoding` を含む行が Decay と GC の 2 つある
3. 検証コマンド3の出力に `default_tools_approval_mode` を含む
4. 検証コマンド4の出力が `OK` (誤判定の再現テスト: エコーされた指示文を含む出力から、最後の判定行だけを拾う)

## 検証コマンド
1. `powershell -NoProfile -Command "foreach ($f in 'scripts/register-tasks.ps1','skills/mcp-setup/register.ps1') { $e=$null; [void][System.Management.Automation.Language.Parser]::ParseFile((Resolve-Path $f), [ref]$null, [ref]$e); if ($e.Count -eq 0) { 'OK' } else { $e } }; 'OK'"`
2. `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/register-tasks.ps1 -WhatIf | Select-String -SimpleMatch "[Console]::OutputEncoding"`
3. `grep -n "default_tools_approval_mode" skills/mcp-setup/register.ps1`
4. `powershell -NoProfile -ExecutionPolicy Bypass -File skills/mcp-setup/register.ps1 -SelfTestSmokeParser`

## 補足
- 検証コマンド4のため、`register.ps1` に隠しスイッチ `-SelfTestSmokeParser` を足す。判定関数 (例 `Get-SmokeVerdict`) に次の入力を渡し、結果が期待どおりなら `OK`、違えば `NG <内容>` を出して終了する (疎通確認などは行わない)。
  - 入力 A: 1 行目が指示文のエコー `user: ... SM_SMOKE_OK の後に件数 ... SM_SMOKE_EMPTY ... SM_SMOKE_FAIL ...`、最後の行が `SM_SMOKE_FAIL connection refused` → 判定は FAIL
  - 入力 B: 最後の行が `• SM_SMOKE_OK 8` → 判定は OK (件数 8)
  - 入力 C: 判定行が無い → 判定は FAIL (「答えが無い」)
- PowerShell 5.1 互換で書き、日本語を含む ps1 は UTF-8 BOM 付きのまま保存する。
- Kimi の `kimi -p` は答えの行頭に `• ` を付けることがある (実測)。
