# PBI-002: OpenSearch (Sudachi 入り) の Docker 環境・インデックステンプレート・検索パイプライン

- 担当モデル: opus
- 依存: なし

## 目的
設計書 (`docs/design/design.md`) 3.3 章のインデックスを載せる OpenSearch を、Sudachi 形態素解析プラグイン入りの単一ノードとしてローカル Docker で動かす。マッピングとハイブリッド検索用の Search Pipeline を JSON ファイルとして用意する (投入は別 PBI のコードが行う)。

## 対象 (新規。リポジトリルート = `C:\Users\owner\dev\shared-memory`)
- `opensearch/Dockerfile` … `FROM opensearchproject/opensearch:3.5.0`。Sudachi プラグイン `https://github.com/WorksApplications/elasticsearch-sudachi/releases/download/v3.6.0/opensearch-3.5.0-analysis-sudachi-3.6.0.zip` を `opensearch-plugin install --batch` で入れる。Sudachi のシステム辞書 (core 辞書。`https://github.com/WorksApplications/SudachiDict/releases` の最新の `sudachi-dictionary-<日付>-core.zip`、URL はバージョン固定で書く) を取得して `system_core.dic` をプラグインが読む場所 (`/usr/share/opensearch/config/sudachi/`) に置き、`opensearch/sudachi/sudachi.json` をそこへ COPY する。
- `opensearch/sudachi/sudachi.json` … `system_core.dic` を使う最小の設定。
- `docker-compose.yml` … サービス `opensearch` (build: ./opensearch, container_name `shared-memory-opensearch`)。環境変数 `discovery.type=single-node`, `DISABLE_SECURITY_PLUGIN=true`, `DISABLE_INSTALL_DEMO_CONFIG=true`, `OPENSEARCH_JAVA_OPTS=-Xms1g -Xmx1g`, `bootstrap.memory_lock=false`。ポートは **`127.0.0.1:9200:9200` のみ** (9600 は公開しない)。名前付きボリューム `opensearch-data` を `/usr/share/opensearch/data` に。`restart: unless-stopped`。
- `opensearch/index-template.json` … 設計書 3.3 章の JSON (settings + mappings) をそのまま。ただしプラグインの実際のフィルタ名・トークナイザ設定で `_analyze` が通るように必要なら調整する (調整したら補足に理由をコメントではなく PBI の報告に書く)。
- `opensearch/search-pipeline.json` … `phase_results_processors` に `normalization-processor` を 1 つ。`normalization.technique: "min_max"`、`combination.technique: "arithmetic_mean"`、`combination.parameters.weights: [0.4, 0.6]` (BM25 → kNN の順)。

## 触らない範囲
- `packages/`, `config.yaml`, `package.json` (別 PBI)
- `docs/` 配下 (読むだけ)
- 既存の他の Docker コンテナ・ボリューム (削除しない)

## 受け入れ条件
1. 検証コマンド1が終了コード 0
2. 検証コマンド2の出力に `"status":"green"` または `"status":"yellow"` を含む
3. 検証コマンド3の出力に `analysis-sudachi` を含む
4. 検証コマンド4の出力の tokens に `東京` と `都庁` が別トークンとして、または `東京都庁` が 1 トークンとして含まれる (Sudachi で分割されていること。エラー JSON でないこと)
5. 検証コマンド5・6がいずれも `"acknowledged":true` を含む
6. 検証コマンド7の出力に `127.0.0.1:9200` を含み `0.0.0.0:9200` を含まない

## 検証コマンド
1. `docker compose up -d --build`
2. `curl -s --retry 30 --retry-delay 3 --retry-all-errors "http://127.0.0.1:9200/_cluster/health?wait_for_status=yellow&timeout=60s"`
3. `curl -s http://127.0.0.1:9200/_cat/plugins`
4. `curl -s -X PUT http://127.0.0.1:9200/pbi002-test -H "Content-Type: application/json" --data-binary @opensearch/index-template.json && curl -s -X POST http://127.0.0.1:9200/pbi002-test/_analyze -H "Content-Type: application/json" --data-binary @<UTF-8 で {"analyzer":"ja","text":"東京都庁で会議をしました"} を書いた JSON ファイル>` (レビュー時に修正: Windows の ACP 932 で -d の日本語が Shift_JIS になるため)
5. `curl -s -X PUT http://127.0.0.1:9200/_search/pipeline/pbi002-pipeline -H "Content-Type: application/json" --data-binary @opensearch/search-pipeline.json`
6. `curl -s -X DELETE http://127.0.0.1:9200/pbi002-test && curl -s -X DELETE http://127.0.0.1:9200/_search/pipeline/pbi002-pipeline`
7. `docker port shared-memory-opensearch`

## 補足
- Windows (Git Bash) で実行する。Docker Desktop は起動済み、WSL2 の vm.max_map_count は 1048576 で設定済み。
- プラグインと OpenSearch のバージョンは一致が必須 (3.5.0 + sudachi 3.6.0)。
- プラグインの設定方法 (sudachi.json の置き場所、`settings_path` やフィルタ名) は `https://github.com/WorksApplications/elasticsearch-sudachi` の README (v3.6.0 タグ) を確認する。
- 辞書の zip URL が 404 なら `gh api repos/WorksApplications/SudachiDict/releases --jq '.[0].assets[].browser_download_url'` などで実在する URL を調べて固定する。
