# PBI-016: README と初期メモリ (この仕組み自体についての知識)

- 担当モデル: sonnet
- 依存: PBI-011

## 目的
別 PC でも clone してコマンド数回で復元できるよう、セットアップと運用の手順を README にまとめる (設計書 `docs/design/design.md` 7章)。あわせて、検索の動作確認用に、この仕組み自体の決定事項を初期メモリとして手書きで 20 件入れる (設計書 10章 ステップ2「手書きの Markdown 数十件で検索を確認」)。

## 対象 (リポジトリルート = `C:\Users\owner\dev\shared-memory`)
- `README.md` (新規) … 構成図 (テキストの箇条書きでよい)、前提 (Windows / Docker Desktop / Ollama / Node 26 / pnpm)、別 PC でのセットアップ手順 (設計書 7.1章: clone → `pnpm install` → `ollama pull qwen3-embedding:0.6b` → `docker compose up -d --build` → `pnpm sm reindex` → `scripts/start-mcp.ps1` → `skills/mcp-setup/register.ps1`)、CLI コマンド一覧 (`docs/design/interfaces.md` 11章)、MCP ツール 3 つの説明、メモリファイルの書式 (front matter の表)、保全の方針 (設計書 7.2章の表)、運用ルール (「`write` の結果は Git の差分を見てから人がコミット」「SQLite は主に使う 1 台だけでコミット」「秘密情報を書かない」「ポートは 127.0.0.1 限定。バインド先を変えるなら OpenSearch のセキュリティを有効に戻す」)、テストの実行方法 (`pnpm test`, `pnpm test:int`)、設計書へのリンク (`docs/design/design.md`, `docs/design/interfaces.md`)。日本語。
- `memories/global/<ULID>.md` を 20 ファイル (新規) … 設計書と `docs/design/interfaces.md` から、1 ファイル 1 事実・1 決定になるように抜き出す (例: 「Markdown が唯一の正で OpenSearch は再構築可能な派生」「ポートはすべて 127.0.0.1」「埋め込みは Qwen3-Embedding-0.6B 1024 次元、モデルを変えたらインデックス名を変える」「ハイブリッド検索の重み BM25 0.4 / kNN 0.6」「再スコアの式」「tier の降格日数」「human_confirmed は warm より下に落ちない」「本文は書き換えず supersedes で新規作成」など)。front matter は `scope: global`、`kind: semantic`、`provenance: agent_verified`、`source_agent: claude`、`created_at: 2026-10-10T00:00:00.000Z`、`tags` は 1〜3 個。id は ULID (26 文字、Crockford Base32) で 20 個すべて別、ファイル名と一致させる。本文は 2〜6 行、最後の行に `出典: docs/design/design.md <章番号>` を書く。

## 触らない範囲
- `packages/`, `opensearch/`, `scripts/`, `skills/`, `docker-compose.yml`, `package.json`, `config.yaml`, `docs/`
- `memories/global/.gitkeep` 以外の既存ファイル (無いはず)

## 受け入れ条件
1. 検証コマンド1の出力が `20`
2. 検証コマンド2の出力 (JSON) の `scanned` が 20 で `invalid` が空配列
3. 検証コマンド3の出力 (JSON) の 1 件目の title が、OpenSearch のポートやループバック (127.0.0.1) に関するメモリ
4. 検証コマンド4の出力 (JSON) の 1 件目の title が、埋め込みモデルに関するメモリ
5. 検証コマンド5の出力に `pnpm sm reindex` と `register.ps1` と `127.0.0.1` を含む

## 検証コマンド
1. `ls memories/global/*.md | wc -l`
2. `pnpm --silent sm index --json`
3. `pnpm --silent sm search "外部から接続できないようにするには" --json`
4. `pnpm --silent sm search "ベクトル化に使うモデルは何か" --json`
5. `grep -o -E "pnpm sm reindex|register.ps1|127.0.0.1" README.md | sort -u`

## 補足
- ULID は `node -e "import('ulid').then(m=>{for(let i=0;i<20;i++)console.log(m.ulid())})"` を `packages/core` ディレクトリで実行して作ってよい。
- 書式の例 (`docs/design/interfaces.md` 2章):

```
---
id: 01JA0000000000000000000000
title: ポートはすべて 127.0.0.1 にだけバインドする
scope: global
kind: semantic
provenance: agent_verified
source_agent: claude
created_at: 2026-10-10T00:00:00.000Z
tags:
  - security
---

OpenSearch・埋め込みサーバー・MCP サーバーはループバックにだけバインドし、PC の外から到達できる入口を作らない。
docker-compose のポート指定も `127.0.0.1:9200:9200` の形にする。
出典: docs/design/design.md 9章
```
- 検証コマンド2〜4 は本番のインデックス (エイリアス `memories`) を使う。OpenSearch と Ollama は起動済み。
