# PBI-024: インデックスに埋め込みの指紋を書き、設定と違えば index を止める

- 担当モデル: (prepare.py の表から)
- 依存: PBI-022

## 目的
埋め込みの設定を変えたあとに `index` を流すと、今は新旧のベクトルが黙って混ざる。インデックスを作るときに指紋を `_meta` に書き、索引作りの前に設定と照合して、違えば `pnpm sm reindex` を促して止める (ADR 0001)。

## 対象
- `packages/core/src/opensearch.ts`: インデックスの `_meta` を読むメソッド `getIndexMeta(index: string): Promise<Record<string, unknown> | undefined>` を足す (`GET /<index>/_mapping` の `<実際のインデックス名>.mappings._meta`)
- `packages/core/src/indexing.ts`:
  - `readTemplate` が、テンプレートの `mappings.properties.embedding.dimension` を `cfg.embedding.dimension` で上書きし、`mappings._meta = { embedding: { fingerprint, parts } }` を足して返す (fingerprint は `embeddingFingerprint(cfg.embedding)`、parts は `fingerprintParts(cfg.embedding)`)
  - `checkEmbeddingCompat(cfg, os): Promise<{ ok: boolean; index: string; indexFingerprint: string; expected: string }>` を export する。エイリアスの先のインデックスの `_meta.embedding.fingerprint` を読み、無ければ `embeddingFingerprint(LEGACY_EMBEDDING)` とみなす。エイリアスの先が無ければ ok
  - `indexIncremental` の最初で、書き込み先を明示されていない (`opts.index` が無い) ときに `checkEmbeddingCompat` を呼び、ok でなければ throw する。メッセージは `埋め込みの設定がインデックス <index> と違います (インデックス <indexFingerprint>、設定 <expected>)。pnpm sm reindex で作り直してください`
- `packages/core/test/indexing.int.test.ts`: 結合テストを足す

## 触らない範囲
- `opensearch/index-template.json` (ファイルの 1024 は残し、読み込み時に上書きする)
- embed.ts、search.ts、app.ts、cli.ts (MCP 起動時の警告は PBI-025 が checkEmbeddingCompat を呼んで足す)
- README.md、.gitignore、scripts/、lab/、docs/experiments/

## 受け入れ条件
1. 検証 1 (結合テスト。トンネル経由の実物の OpenSearch と Ollama) が exit 0・`# fail 0`。次のテストを含むこと
   - `ensureSetup` で作ったテスト用インデックスの `_meta.embedding.fingerprint` が `embeddingFingerprint(cfg.embedding)` と等しく、`embedding.dimension` が設定の値
   - 設定の `embedding.revision` を 1 にした cfg で `indexIncremental` を呼ぶと、`pnpm sm reindex` を含むエラーで止まり、ドキュメントが書かれない
   - 同じ cfg で `reindexAll` を呼ぶと成功し、新しいインデックスの `_meta` が新しい指紋になる
   - `_meta` の無いインデックス (テンプレートから `_meta` を除いて直接作り、エイリアスを付けたもの) は、LEGACY_EMBEDDING と同じ指紋の設定なら `checkEmbeddingCompat` が ok、revision を変えた設定なら ok でない
2. 検証 2 (型チェック) が exit 0
3. 検証 3 (単体テスト全体) が exit 0・`# fail 0`
4. 検証 4 (既存の結合テスト全体) が exit 0・`# fail 0`
5. 検証 5 が出力なし・exit 0

## 補足
- 仕様は `docs/specs/pluggable-embedding-and-rerank.md` の「埋め込みの指紋とインデックス」、決定は `docs/adr/0001-embedding-fingerprint-excludes-url.md`。
- 結合テストは `packages/core/test/int-helpers.ts` の `makeTestEnv` を使う (名前が `test-` で始まるインデックス・エイリアスを作り、cleanup で消す)。本番のエイリアス `memories` とその先のインデックスには触れない。
- テストの cfg は実リポジトリの config.yaml から作られ、その embedding は LEGACY_EMBEDDING と同じ指紋になる (url と batch_size は指紋に入らない)。今の本番のインデックスには `_meta` が無いので、このままの設定なら止まらない。これが壊れないこと。
- `reindexAll` は `indexIncremental(cfg, deps, { index })` を呼ぶので、照合を通らずに新しいインデックスへ書ける。この流れを変えない。
- memory-store (MCP の write) と import は indexIncremental を通るので、照合は自動でかかる。
- revision を変えた cfg は `structuredClone` で作り、元の env.cfg を書き換えない。埋め込みは Ollama を実際に呼ぶので、テストのメモリは 1〜2 件の短い本文にする。
