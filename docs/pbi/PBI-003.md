# PBI-003: core の設定読み込み・front matter 検証・秘密情報検出

- 担当モデル: sonnet
- 依存: PBI-001

## 目的
メモリ (Markdown) の front matter を検証・読み書きする基盤と、`config.yaml` の読み込み、秘密情報らしき文字列の検出を core パッケージに実装する。インデクサと MCP サーバーの両方が使う。

## 対象 (リポジトリルート = `C:\Users\owner\dev\shared-memory`)
- `packages/core/src/config.ts` … `docs/design/interfaces.md` 1章 (`Config`, `findRoot`, `loadConfig`)
- `packages/core/src/frontmatter.ts` … 同 2章 (定数・型・`scopeToDir`・`validateMeta`・`parseMemoryFile`・`serializeMemory`・`memoryRelPath`)
- `packages/core/src/secrets.ts` … 同 3章 (`findSecrets`)
- `packages/core/test/config.test.ts`, `packages/core/test/frontmatter.test.ts`, `packages/core/test/secrets.test.ts` (新規)

## 触らない範囲
- `packages/core/src/index.ts` (再エクスポートは作成済み) と、上記以外の `packages/core/src/*.ts`
- `package.json`, `config.yaml`, `docs/`

## 受け入れ条件
1. 検証コマンド1の TAP 出力が `# fail 0` で、`# pass` が 15 以上
2. 検証コマンド2が終了コード 0
3. テストが少なくとも次を確認している: (a) 正しい front matter を parse できる (b) 必須項目欠け・列挙外の値・ULID でない id・id とファイル名の不一致・scope とディレクトリの不一致がそれぞれエラーになる (c) `serializeMemory` → `parseMemoryFile` で元に戻る (tags・supersedes あり) (d) `scopeToDir` の 3 形式と不正値 (e) `findSecrets` が AWS キー・GitHub トークン・`sk-ant-`・秘密鍵ブロックを検出し、普通の日本語文では空配列 (f) `loadConfig` がリポジトリの `config.yaml` を読み `memories_dir` が絶対パスになる

## 検証コマンド
1. `node --test --test-reporter=tap packages/core/test/config.test.ts packages/core/test/frontmatter.test.ts packages/core/test/secrets.test.ts`
2. `pnpm typecheck`

## 補足
- 仕様の正本は `docs/design/interfaces.md` の 0〜3章。0章の TypeScript の制約 (拡張子 `.ts` 付き import、enum 禁止など) に従う。
- YAML は `yaml` パッケージ (`import { parse, stringify } from "yaml"`)。`created_at` が YAML で Date に変換された場合は ISO 文字列へ戻す。
- テストで使う ULID は固定値 (例 `01JA0000000000000000000000`) でよい。
- テストに秘密情報の例を書くときは、実在しない値を文字列連結で組み立てる (例 `"AKIA" + "ABCDEFGHIJKLMNOP"`)。
- front matter の例:

```
---
id: 01JA0000000000000000000000
title: OpenSearch のポートはループバック限定
scope: global
kind: semantic
provenance: human_confirmed
source_agent: human
created_at: 2026-10-10T00:00:00.000Z
tags:
  - security
---

本文
```
