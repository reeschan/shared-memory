# 橋渡しかどうかは kind やタグでなく scope (作業空間) で表し、scope なしの検索から常に除く

AI どうしの橋渡し (進み具合・引き継ぎ・ref・スナップショット) と知識が、同じ検索に混ざっていた。kind は「古くなるか」の軸で、episodic にも知識があり、semantic にも橋渡しがあるので、この区別に使えない。そこで、atelier がすでに使っている作業空間 (`project:work.` で始まる scope) を唯一の軸にした。橋渡しは作業空間にだけ書き、scope を付けない検索は作業空間を常に除く。作業空間を引くのは、scope を明示したときと、`include_workspaces` を付けたとき (resume) だけにする。

## Considered Options

- **kind に値を足す (例えば `relay`)**: kind は freshness のしきい値の鍵でもあり、「古くなるか」と「橋渡しか」の 2 つの軸が 1 つの値に混ざる。既存のメモリの kind は書き換えられない (本文と front matter は不変) ので、移行もできない。
- **タグ (`relay`) を必須にする**: scope と二重管理になり、作業空間にあるのにタグが無い、またはその逆のずれが生まれる。
- **finish で閉じた作業空間だけを除く / 30 日アクセスが無ければ除く**: 閉じた印が要るうえ、作業中のほかの作業の橋渡しは混ざり続ける。

## Consequences

- 汚れの原因は軸が無いことではなく、橋渡しを global・repo に書いたことだった。そのため決まりを、エージェントが必ず読む `write` のツール説明、`~/.claude/CLAUDE.md`、atelier に書く。決まりが守られなければ、この既定は効かない。
- scope なしの検索に頼って作業空間を読んでいた利用者は、`include_workspaces` か scope の明示に移る必要がある。
